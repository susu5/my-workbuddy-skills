# 风格系统与选择

机器注册表：[style-registry.json](style-registry.json)。完整离线实样：[style-preview.html](../assets/style-preview.html)。六种大胆方向用于用户希望看到明显不同模板的场景；基础四种保留精确核对与旧报告兼容用途。没有固定默认风格。

## 六种大胆方向

| 风格 / ID | 构图与正文节奏 | 适合 | 防止退化成同一模板 |
| --- | --- | --- | --- |
| 瑞士构成 `swiss-impact` | 黑白红；超大无衬线标题与证据不对称并置；编号摘要；粗线分节与整齐表格 | 决策简报、经营快报 | 不做圆角卡片墙；标题与数据有尺度差；长解释正常字号 |
| 咨询绿皮书 `consulting-green` | 独立深绿封面；奶油内页；衬线标题；纵向论点摘要；章节眉与证据对照 | 正式方案、管理层分析 | 封面与内页明暗切换，正文强调论证层次，与黑金宽幅结果章分开 |
| 工程蓝图 `engineering-blueprint` | 蓝色细网格；标题与关系图双区；步骤轨道、角色交接、异常规则 | SOP、流程、模型说明 | 节点和箭头有真实含义，网格只作背景 |
| 黑金年报 `annual-noir` | 近黑与暖金；单个核心结果主导封面；衬线标题；宽幅数据带、细线与留白 | 年度复盘、专题成果、会议 | 全页深色宽幅节奏；无可靠核心数值时用文字，不复制咨询的奶油内页 |
| 波普数据 `data-pop` | 钴蓝＋酸橙；海报标题色块、粗黑框；摘要分格；图表与表格拼接 | 运营战报、活动复盘 | 关键区强色，正文可连续阅读；装饰酸橙色不代表业务表现良好 |
| 东方留白 `oriental-ink` | 纸白、墨色、朱红短题签；竖题与横排正文；衬线标题；疏朗图文 | 策略、案例、长文、流程说明 | 竖排仅用于短题签，手机改横排；表格横排；不伪造印章认证 |

基础四种：清晰商务 `clean-table`（白底深蓝、整幅精确表）；现代数据 `light-glass`（浅底面板、蓝紫分组）；温暖编辑 `editorial-brief`（暖白单栏、衬线标题）；深色研判 `dark-analytics`（深蓝灰数据面板）。`light-glass` 是兼容参数，不使用玻璃模糊。

## 推荐与预览

1. 看读者任务、内容重心与展示环境，推荐**一种**并说明具体原因。SOP 通常先看工程蓝图，正式长篇方案先看咨询绿皮书；推荐仍须结合实际内容。
2. 新报告通常展示三个候选：一个最适合当前任务，另外两个在构图和阅读节奏上明显不同。用户要大胆或全部方向时展示上表六种；需要稳健或兼容时加入基础风格。
3. 已明确选择或授权代选时直接制作并记录依据，不重复确认。未授权时等待选择，同时核对材料。
4. 用同一份内容做首屏＋正文片段对比。各版数字、范围、图表坐标与限制一致；允许视觉重组，不能颠倒流程、排名或推导关系。

每个方向在构图、字体尺度、章节节奏、证据组织中至少三项有明显差别。检查去色后的轮廓和正文，仍能区分才算通过。内容精度与语义颜色规则保持一致。

## 颜色与字体

- 无衬线：`"Microsoft YaHei","PingFang SC",system-ui,sans-serif`；衬线标题：`"Songti SC","SimSun",serif`；东方题签可用 `"KaiTi","STKaiti","SimSun",serif`。无需下载字体。
- 大数字有名称、单位、范围与事实/假设状态。没有可信数值就用文字，不凑 KPI。
- 蓝紫等区分类别；红绿仅在既有证据支持不利/有利时作为业务状态，配合文字。品牌装饰色与状态分开。
- 浅色字体、金色和酸橙背景分别检查对比度；不用发光和阴影代替层级。

## 选择记录与兼容

与业务内容包分开保存，示例仅说明格式：

```json
{
  "recommended": "engineering-blueprint",
  "reason": "本次是多角色交接流程，步骤、输入和完成标准需要相邻呈现。",
  "offered": ["engineering-blueprint", "consulting-green", "oriental-ink"],
  "selected": "engineering-blueprint",
  "selection_basis": "user_choice",
  "user_response": "选工程蓝图"
}
```

`selection_basis` 为 `user_choice`、`explicit_style` 或 `delegated`；持续授权可记为 `delegated` 并保留适用原话。`user_choice` 至少展示三个不同候选；明确点名或授权代选可只记录实际展示的非空候选，须包含推荐和最终选择。候选不重复，无未知 ID。

原有四种候选的记录继续有效，新记录不要求列全十种。脚本只能检查记录结构和主题匹配，仍须核对真实对话；不能编造用户原话。预览切换不自动写成正式选择。
