# 四种报告风格与选择

四种风格共享清晰表达、正确逻辑、图表对比、语义颜色和内容保护要求。风格改变视觉组织，不改变结论、数值、证据强度、章节顺序或比较条件。

## 每次展示的完整选项

向用户展示以下四行，并根据当前内容只标出一个推荐项。理由要具体，例如“本次主要比较首句发送、回复和课时分组，现代数据便于把每项比例图与人数表放在一起”；不要只说“比较美观、适合老板”。

| 风格名称 | 视觉特点 | 适用内容 |
| --- | --- | --- |
| 清晰商务 | 白底、深蓝标题、平直分区、清楚的表头和行线，重点克制 | 正式汇报、多对象核对、表格为主的经营报告 |
| 现代数据 | 浅灰底、白色内容区、蓝紫分组，相关小图成组展示 | 转化率、趋势、分层对比、多维数据分析 |
| 温暖编辑 | 暖白底、深色正文、中文衬线标题、连续单栏章节 | 月度总结、策略说明、文字与证据结合的长报告 |
| 深色研判 | 深蓝灰底、高对比浅色文字、亮蓝重点、清楚的图表边界 | 专题研判、会议展示、适合深色环境的报告 |

可以给用户打开 [四种风格实样](../assets/style-preview.html)，其中数据是明确标注的虚构示例。预览不替代对本次报告内容的推荐或完整选项表。

## 如何推荐

1. 先判断本次读者如何阅读：逐项核对、观察趋势、连续阅读，还是会议讲解。
2. 再看主要证据形式：密集表格优先清晰商务；多组数据图表优先现代数据；较长解释优先温暖编辑；有明确深色展示需求时优先深色研判。
3. 内容混合时按主要阅读任务推荐一种；说明选择依据，避免给出多个“同样推荐”。用户的明确选择始终优先。
4. 没有固定默认风格。信息少时按已知内容做有依据的暂定推荐，请用户选择，不先生成成品。

## 具体设计

| 项目 | 清晰商务 | 现代数据 | 温暖编辑 | 深色研判 |
| --- | --- | --- | --- | --- |
| 页面与正文 | 白底、深蓝灰文字 | 浅灰底、深色文字、白色区块 | 暖白底、深褐色文字 | 深蓝灰底、近白文字 |
| 标题组织 | 左对齐，深蓝底线建立层级 | 页首竖向蓝色标记，简短元信息 | 中文衬线标题，章节序号和留白 | 深色页首、上方蓝色细线、结论边线 |
| 区块 | 平直分隔、少圆角、无阴影 | 小圆角、细边框，区块边界明确 | 连续单栏，不堆叠卡片 | 深浅两层面板，边框清晰 |
| 表格 | 表头下线较强，交替行底色，数字齐列 | 蓝灰表头，重点比较列用字重突出 | 暖灰表头、横线为主，行间距略宽 | 深色表头、清楚行线，说明文字也保持对比 |
| 图表安排 | 完整宽度，先精确对比表，再解释图 | 相关小图最多两列，复杂图完整宽度 | 单列图文衔接，图题与解释相邻 | 相关图可两列，数值和坐标直接标注 |
| 字体 | 全文清楚的系统无衬线字体 | 全文系统无衬线字体，数字等宽排列 | 仅标题可用系统中文衬线，正文与数字无衬线 | 全文系统无衬线，重点用字重区分 |
| 禁止 | 拆成大量小卡片、过密表格 | 玻璃模糊、渐变堆叠、仪表盘墙 | 多栏报纸布局、装饰引语墙 | 霓虹、发光、闪烁、纯黑低对比表格 |

所有风格保持同样的阅读顺序和完整信息，不能为了风格删表格、藏限制或少画必要的图。只有关系简单、标签不长的小图可以两列，长中文标签、复杂坐标、密集图例必须整行展示。

## 颜色和字体的作用

- 蓝、紫等用于区分本次报告的比较对象；同一对象在本报告的图表与表格中保持一致，不把这种映射永久绑定到业务实体。
- 实际值、预估值同时有文字标记；预估在图上用虚线。
- 红与绿只表达已有证据支持的业务不利或有利含义，不表示“组甲/组乙”，不因差值正负自行判断好坏。
- 黄色提示待确认、条件不一致等限制；不足样本使用清楚的中性色文字，不能淡到难读。
- 表头、关键数值、比较差异可加粗；不用大面积高亮和整段粗体。颜色之外始终有完整标签。

## 兼容参数

保留旧参数以兼容既有生成脚本；显示给用户的是新名称。`light-glass` 只是兼容键，实际视觉不再使用玻璃效果。

| 对外名称 | 内部参数 |
| --- | --- |
| 清晰商务 | `clean-table` |
| 现代数据 | `light-glass` |
| 温暖编辑 | `editorial-brief` |
| 深色研判 | `dark-analytics` |

## 选择记录

选择记录与业务内容包分开保存。示例中的选择必须替换为本次真实对话结果：

```json
{
  "recommended": "light-glass",
  "reason": "本次主要比较多个分组的转化率，需要让比例图与人数表相互对应。",
  "offered": ["clean-table", "light-glass", "editorial-brief", "dark-analytics"],
  "selected": "clean-table",
  "selection_basis": "user_choice",
  "user_response": "选清晰商务"
}
```

`selection_basis` 只能为：`user_choice`（展示后选择）、`explicit_style`（请求中已指定）或 `delegated`（明确授权代选）。后两种也必须展示推荐和全部选项，不重复追问。`user_response` 保留实际选择或授权的文字，不自行编造。没有回复时不写入有效选择，不生成报告成品。

检查脚本只能校验记录是否完整、参数是否匹配，不能证明用户真实表达过授权；执行者必须核对对话。
