# 情景模型的内容交接与交互验收

仅用于用户需要情景对比或参数交互、且内容阶段已确认模型的报告。报告 Skill 实现模型的展示与输入反馈，不自行定义经营指标、成本口径、因果关系或新的计算公式。

## 先确认模型口径

内容包或已确认文字须提供：

- 模型名称、指标含义、单位、时间粒度、来源和适用限制。贡献额、毛利和自由现金流不能仅因名称相似互换。
- 输入参数的含义、分母、单位、默认值、允许范围、步长、事实或假设状态，以及相互约束。
- 固定参数和公式；公式中的百分比用 0–1 还是 0–100，四舍五入在哪一步执行。
- 默认及必要边界情景的预期结果，用于独立核对；预期值必须来自内容阶段，不能从待检查页面反向抄录。
- 敏感性采用的变化量和评级依据。不同步幅或样本规模下的总变化不能直接当作统一的敏感度排名。

来源或关键公式缺失时解决相应输入，不能用一个“可交互”组件掩盖口径未确认。静态情景表也可以满足测算任务，不强制交互。

## 展示组件

- 基准区域明确写“基准情景测算”及关键前提；实际观察值用不同文字标签。
- 关系简单时用 `.scenario-grid` 将 `.parameter-panel` 与 `.result-panel` 相邻排列；窄屏改为上下排列。输入、当前值、单位同时可见。
- 每个输入用关联的 `label` 或可访问名称，原生输入能用键盘调整；当前结果有明确名称。需要播报时用简短的 `aria-live` 结果摘要，避免播报整张敏感性表。
- 提供“恢复基准参数”按钮。基准值来自同一模型输入，不另写一套默认值。
- 所有关联结果由同一当前状态渲染：数值、单位、标签、颜色、表格和图。若顶部结论或对比表保留基准快照，紧邻注明“原始基准，未随当前参数更新”；不得让动态结果和固定结论看起来属于同一情景。
- 计算保留必要精度，展示时统一格式化。先判断实际业务含义再着色；不得永久把“基准列”设为绿色，或用同一红色同时表示亏损与高敏感度。
- 核心前提直接可见，不能仅在页脚写“均待验证”。改变参数不应自动强化结论或产生未经确认的业务建议。

输入声明示例（百分比按 0–100 显示）：

```html
<label for="conversion">转化率（目标客户中的购买占比）</label>
<input id="conversion" type="range" min="0" max="100" step="1"
       value="20" data-value-kind="probability" data-value-scale="percent">
```

`data-value-kind="probability"` 表示概率，`data-value-scale` 取 `percent` 或 `fraction`（0–1）。人数可用 `data-value-kind="count"`。这些属性用于静态边界检查，不替代内容阶段的业务约束。

## 敏感性表达

- 区分“相对基准的下档变化”“相对基准的上档变化”和“上下档总跨度”。仅当单侧幅度相等时才能用 `±`，且其数字是单侧幅度。
- 例如基准 100、下档 80、上档 120：单侧是 `±20`，上下档跨度是 `40`。基准位于区间端点时写区间或单侧变化，不写对称 `±`。
- 概率不能小于零或超过 100%；人数不能小于零。到达边界后使用有效区间，并明确说明步幅已调整；不静默计算负转化率。
- 情景超过滑块允许范围时标明扩展范围及理由，或使用已确认的边界；有相互约束的参数要一起验证。

## 交互验收

1. 默认输入与内容阶段提供的预期值一致。
2. 分别调整每个参数，核对影响方向及相关区域；固定基准快照有清楚标签。
3. 检查零值、上下限和能产生负结果的有效情景：无非法概率、负人数、`NaN`、无穷值或过期颜色。
4. 核对敏感性跨度、单侧变化、变化单位和评级依据。
5. 恢复基准后全部输入及动态结果恢复一致。
6. 键盘、窄窗口及标签可用；没有仅靠颜色或悬停传递的关键值。

`validate_report.py` 只检查静态输入边界、部分标签及报告结构，不执行 JavaScript，不验证公式正确性、状态同步、颜色含义或完整可访问性。执行者须另行记录模型核对和浏览器操作结果；受限时明确列出未完成项。
