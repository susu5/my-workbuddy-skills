# 报告表达、图表与验收

这些要求适用于全部风格。目标是让读者看懂“比较什么、相差多少、能说明什么、不能说明什么”。

## 表达和阅读顺序

- 标题说明对象与问题；先给已确认结论，再给数据证据、解释和适用限制。不要以代码、处理日志、文件清单开篇。
- 使用完整中文名称，例如“首句已发送且客户已回复”“买单人数”“转化率”。避免“已发已回”“日比”等需要猜测的表达。
- 专业简称确有必要时先写全称与解释。AI、HTML 等读者熟悉或已定义的名称可保留；不凭空创造业务缩词或等级。
- “转化率高”“执行质量高”是不同判断，不能靠相同颜色暗示联系。事实、可能原因、待验证事项和建议分开写。
- 保留原始指标和结论；无法确认简称的全称时先核实，不能自行扩写。内容不适用时不强行设置问题、机会和负责人。
- 页首放标题、时间范围、简短结论和核心对比。不要为了把全部内容塞进首屏而缩小字号。
- 关键限制放在对应结论附近，例如“这两组比较条件不同，不能据此判断效果”；完整方法和证据可在附录。影响判断的限制不能只藏在折叠区。

## 按阅读任务组织内容

详细骨架与排版字段见 [report-structures.md](report-structures.md)。新增流程方案 `process-playbook`：目标与边界 → 步骤与交接 → 角色/输入/完成标准 → 异常规则 → 已确认推进动作。

内容结构与视觉风格分开。根据任务采用下列结构，允许混合必要组件；不要为了模板完整制造结论或删减已确认内容。

| 内容结构 | 内部标记 | 主要阅读任务 | 建议组织 |
| --- | --- | --- | --- |
| 决策简报 | `decision-brief` | 快速理解差别、条件和下一步 | 总体判断 → 核心结论 → 必要对比或解释 → 已确认动作 |
| 深度分析 | `evidence-report` | 核对多项数据及解释 | 总体判断 → 核心结论 → 按问题组织的证据与精确表 → 解释、限制、动作 |
| 情景测算 | `scenario-model` | 理解已确认参数如何影响结果 | 基准情景及前提 → 参数与结果 → 公式口径 → 情景对比或敏感性 → 成立条件 |

- 新模板在 `body` 的 `data-report-kind` 写入内部标记；旧报告未写该属性时按深度分析兼容检查。
- 首屏的结论区可以用少量并列卡片、短段落或连续条目。只有对比关系明确且内容短时才并排；通常两至三项即可，不为凑数补出结论。长解释放在后续证据区。
- 结论组件按“对象或判断 → 关键数值/证据 → 范围、证据状态与条件”组织。结论没有可信数值时用文字，不填伪指标。
- 每节标题说清回答的问题，简短摘要说明该节能支持什么；正文用最适合该问题的表、图、公式或解释。序号可辅助定位，标题仍使用 `h2`/`h3`。
- 同一组数据可以在结论区摘要、在证据区拆解，但两处承担不同任务并保持口径一致。不要重复堆放等价表格和图。
- 行动表仅在有已确认动作时使用；没有负责人、预期收益或优先级时不生成占位列。限制可以独立成段，避免把所有长解释塞入五列表格。
- 模板保留 `summary`、`report-body`、`notes` 供导航和检查；`key-metrics`、`priority-findings` 是可选组件。静态检查不再要求每份报告必须有表格；必要证据的完整性由内容包与人工核对保障。

## 表格：给出精确值

- 多对象、多个指标、分组结果和行动清单优先用表格；短结论可用段落，不把每句话变成表格。
- 每个单元格尽量只表达一个指标，不把“买单人数/总人数/转化率/差值”挤成一串符号。人数、比例、差异按列对应。
- 表头写全名称和单位。文字左对齐，数字右对齐，数字使用等宽排列；同一指标保持原有小数精度。
- 比例有清楚的分子、分母和数据时间。差异要区分百分点与相对变化；只有内容包已有差异值时才能显示，不在排版阶段补算。
- 主要表格优先四至五列，最多七列、每张最多十行数据。长表按业务意义拆分并重复表头，保留全部数据及原顺序；不靠缩字或内部滚动解决。
- 比较组与对照组放在相邻行或列。同条件对比写明条件。缺失显示“未提供”及原因，零值显示“0”，不能互相替代。
- 表格标题或相邻正文说明该表比较的问题。列头用 `th scope="col"`，行头适合时用 `th scope="row"`。

## 图表：解释差异与趋势

- 根据独立分析问题安排多张图，不设两张上限；没有可靠数据时不强制凑图。每张图和对应精确值表相邻，不连续堆放没有解释的图。
- 分组比较用条形图，时间变化用折线图，分布用合适的分布图。避免三维图、仪表盘墙、大量饼图和装饰性曲线。
- 标题说明指标、比较对象和日期；轴、单位、分组名称、数值直接可见，不能只靠鼠标悬停。
- 条形图从零开始；同一组小图保持一致范围，跨图比较不能分别放大。比例轴的最大值可按阅读需要设置，但标注清楚，不能伪装成百分之百。
- 图表中的人数、比例、标记值只能来自确认过的数据。允许为 SVG/CSS 坐标做渲染换算，但不补算业务指标。
- 样本数和缺失情况直接说明。不对缺失点补零、插值或连线；小样本不给强结论。显示已提供的不确定区间，不能自行计算。
- 内嵌 SVG 使用可访问名称（`role="img"` 与 `aria-labelledby`/`aria-label`）及文字说明；CSS 条形图保留真实文本标签和值。

## 重点和颜色

| 内容含义 | 类名 | 要求 |
| --- | --- | --- |
| 核心实际值 | `metric-primary` | 主色、适度加粗，含义清楚 |
| 预估值 | `metric-forecast` | 写明预估、截止时间，图中虚线 |
| 普通比较组 | `group-a`、`group-b` | 蓝紫等中性类别颜色，同一报告一致 |
| 明确不利变化 | `delta-negative`、`is-problem` | 红色加说明，不因负号自动使用 |
| 明确有利变化 | `delta-positive`、`is-opportunity` | 绿色加说明，不因正号自动使用 |
| 原因或条件待确认 | `is-uncertain` | 清楚的黄褐色文字或浅背景，并写出限制 |
| 普通说明 | `is-neutral` | 可读的中性色 |
| 样本不足或无法判断 | `is-insufficient` | 可读的中性色并显示具体限制，不能淡化到难读 |

颜色不是唯一信号，同时使用全称、标签、字重或线型。关键数值、结论提示、普通说明保持清楚层级，不给整页涂色。不要永久固定渠道、销售人员或产品的颜色。

## 版面和技术

- 主内容宽度通常 1100 至 1240 像素，桌面左右留白至少 24 像素，手机可为 16 像素。主表和复杂图完整宽度；简单相关小图可两列。
- 正文约 18 像素，表格 16 至 18 像素，说明和图表标签至少 15 像素。正常阅读尺寸，不默认大字版；内容过密先调整结构。
- 只用系统字体；中文正文无衬线，咨询、年报、东方与温暖编辑的标题可用中文衬线。数字保持同一字体和等宽排列。
- 普通文字目标对比度至少 4.5:1；高亮、黄色提示、灰色说明和深色主题均需要检查。不可只测正文颜色。
- 标题、导航按文档流排列，不浮盖内容。不要自动播放、闪烁、装饰动画或玻璃模糊。普通纵向页面滚动，无页面横向溢出和表格内部滚动。
- 单文件 `<!DOCTYPE html>`、`lang="zh-CN"`、UTF-8；内嵌 CSS、JavaScript、SVG，无外部字体、图片、脚本、网络请求。普通来源超链接可保留，不属于渲染依赖。
- 延续现有交付范围，不放打印按钮、打印专用样式、保存 PDF 或打印说明；用户明确另有要求时再调整。折叠只用于次要明细，键盘可操作。
- 不强制每份报告套同一套经营指标。模板占位区可以按已确认内容调整，主要结论和对比仍须清楚可寻。
- 标题、数字、正文与说明建立层级，不靠缩小说明换取首屏容量。首屏是否合适以实际显示为准，名为 `first-screen` 的类本身不是验收依据。
- 各风格可复用语义组件，构图仍按独立方向执行，见 [style-themes.md](style-themes.md)。复用数据与组件不等于复用同一个封面和正文节奏；避免卡片墙。
- 专题参数交互读取 [scenario-models.md](scenario-models.md)。静态报告无需为了互动增加滑块；模型缺少已确认口径时先解决内容输入。

## 检查内容一致性

自动检查可读内容包中的标题、日期、结论、关键指标和主要发现。可以添加 `presentation_checks` 数组，让脚本按表格或图表范围核对准确顺序，例如：

```json
{"presentation_checks": [
  {"id": "comparison-table", "text_sequence": ["首句已发送", "1,000", "80", "8.0%", "首句未发送", "1,000", "50", "5.0%"]}
]}
```

每项 `id` 对应 HTML 中唯一元素，序列中的文字应直接来自已确认内容。先核对数据再建立记录，不能从待验收 HTML 反向抄录，形成自证。该检查能发现丢值、换值和顺序问题，不能验证业务计算或确认整份报告无遗漏；仍须人工逐项核对。

## 验收清单

- 本次已展示推荐理由、实际候选（通常三种；大胆方向可展示六种），并有真实选择或代选授权；HTML 的风格与记录一致。
- 没有乱码、未替换字段、重复锚点、失效内部链接、外部渲染依赖。
- 全部数字、图表、比较对象、范围、限制与已确认内容一致；缺失和零值区分。
- 多图多表帮助理解，不重复堆砌；普通类别颜色与业务好坏没有混淆。
- 实际检查 1440×900、1280、390 和 320 像素宽度，标题导航无重叠，表头与长文本不截断，无横向溢出，重点容易找到。
- 深色与浅色背景下，正文、图表标签、备注和提示均可读；操作可用。
- 自动检查和实际浏览器检查分别记录，不把静态通过写成完成了视觉、统计或可访问性验收。
- 首屏能识别报告对象、主要判断、关键证据及影响判断的条件；没有为了挤进首屏缩字或隐藏限制。
- 章节标题与证据回答同一问题；表格、图表和解释各自有明确用途，空组件已移除。
- 有情景模型时，按模型参考完成动态更新、边界、重置与基准标签检查；波动范围、百分点、相对变化不混用。
