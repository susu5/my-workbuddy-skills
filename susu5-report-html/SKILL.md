# SUSU5 报告 HTML

当前版本：**v3.0.0** · 2026-10-08。

把已确认的内容做成便于判断、核对和执行的报告。风格差异必须体现在构图、字体层级、阅读节奏和证据组织；换颜色不能算另一套模板。大胆设计仍须保留完整证据、限制与正常阅读字号。

## 调用与边界

- 用户提出或确认 HTML 报告、分析、总结、方案、流程文档，以及已有报告的展示优化时调用。不必等待用户再点名排版工具。
- 内容尚未完成分析时承接 HTML 输出要求；由内容分析流程确认数据与判断。本技能负责展示，不能新增指标、公式或未经确认的因果解释。
- 代码教学、网站应用、邮件模板不属于自动触发范围。
- 修改本技能、维护模板、展示虚构风格实样时直接执行维护，无需启动业务报告的选风格流程。

## 先判断阅读任务，再推荐风格

读取 [风格与选择](references/style-themes.md) 和 [报告骨架](references/report-structures.md)。三个维度分开决定：

1. **骨架**：快速决策用 `decision-brief`，核对证据用 `evidence-report`，执行与交接用 `process-playbook`，探索已确认模型用 `scenario-model`。按内容判断，通常不另加一轮提问。
2. **风格**：根据读者、主要内容和场景推荐一种。新报告通常展示三个构图差异明显的候选及具体理由；用户要看更多模板或大胆方向时展示六种大胆风格，附完整预览。原四种基础风格仍可选。
3. **交互**：默认普通长页面。导航、次要明细折叠可按需使用；筛选或参数输入只在帮助阅读且有已确认内容时加入。不为美化增加滑块、主题开关或前端框架。

选择遵循真实对话：

- 用户已明确风格、已选定当前报告、明确授权代选，或给出适用于本次的持续偏好时直接执行，不重复确认。改数据、改错和检查重试沿用已选风格。
- 尚无选择或代选授权时展示候选并请求选择，工具可用时用 `request_user_input_async`。等待期间继续核对材料。预选、超时和未回复不能当作同意。
- 用户要求重新设计或阅读场景实质改变时重新判断；已有明确指示足够时不再设审批。
- 将真实推荐、实际展示的候选、选择及依据存为独立 JSON，见风格参考。不改业务内容包，不虚构授权。

用户要求预览时，用本次同一份已确认内容制作有代表性的首屏和正文片段，各版数字、范围和限制一致。不要只给色卡。通用 [十种风格实样](assets/style-preview.html) 全部使用明确标注的虚构数据，不代表真实业务结论。

## 内容保护

优先使用已验证的 JSON 内容包，也可使用已确认文字或表格。保留 `display_value`、结论强度、比较条件、时间范围、样本、限制、动作、负责人和有意义的顺序。缺失不填零，相关不写成因果，假设不写成事实。不从结论反推图表，不在排版阶段补算差值或重新排名。

允许拆段、导航和有依据的全称表头。结构可按阅读任务调整，流程先后、证据推导、排名和比较组顺序不得被设计打乱。关键限制紧邻相关结论，不能只藏在附录或折叠区。矛盾先解决，不能通过突出有利数字掩盖。

## 制作

读取 [表达与验收](references/html-design-and-acceptance.md)。组合工作骨架，再填入已确认内容：

```powershell
python scripts/render_report.py --theme engineering-blueprint --kind process-playbook --scaffold --out <工作骨架.html>
```

也可准备排版字段 JSON，用 `--values <字段.json>` 输出待验收报告。格式见 [报告骨架](references/report-structures.md)。渲染器只拼装模板，不做业务计算；骨架含占位符，不能作为成品交付。

- 基础样式来自 `assets/report-template.html`，封面来自 `assets/layouts/`，正文来自 `assets/structures/`；预览调用同一渲染路径。注册源为 [style-registry.json](references/style-registry.json)。
- 首屏回答对象、总体判断、关键证据与成立条件。适合时用“一张解释图＋一句结论”；没有可靠关系时用文字，不强行画图。
- 章节回答具体问题。精确值用表，差异、趋势或关系用图；数量由问题决定。没有已确认动作或负责人时不补占位行动表。
- 一份成品只用一种风格。大标题、主视觉与装饰色服务真实信息，不伪造数字、印章、认证、评级或趋势。
- 正文约 18px，说明和图表标签至少 15px，表格 16–18px。窄屏调整布局和拆表，不缩字、裁切或隐藏关键条件。
- 单文件、UTF-8、`lang="zh-CN"`，内嵌 CSS/JavaScript/SVG，中文系统字体；无 CDN、在线字体、外部图片或网络请求。来源超链接可保留。
- 正常上下滚动，无表格内部滚动。延续现有范围，不添加打印、PDF、自动播放或装饰动画。用户另有明确要求时再调整范围。
- 仅在已确认情景模型时读取 [scenario-models.md](references/scenario-models.md)，核对参数、默认值、边界、公式和预期结果后实现。

## 验证与交付

```powershell
python scripts/validate_report.py <报告.html> --theme <风格ID> --style-selection <选择.json> --require-style-selection --content-package <内容包.json>
```

没有内容包则省略最后一项，人工逐项核对。`presentation_checks` 可检查表图中的准确值与顺序，不能从待检查 HTML 反抄核对记录。

再实际检查 **1440×900、1280、390、320px**：

- 首屏判断与条件可见，标题、导航和长中文不重叠，无横向溢出、截断或内部滑动。
- 表格与图表值相同，标签与比较对象清楚；普通文字对比度目标 ≥4.5:1，说明、语义提示和封面分别核对。
- 导航、折叠、输入及重置可用键盘操作，焦点可见；无控制台错误和外部资源请求。无交互报告关闭 JavaScript 后仍可阅读。
- 对比模板时检查首屏及一段正文；忽略颜色后，构图、标题层级、证据组织、章节节奏至少三项明显不同。不同主题名不算视觉验收。
- 情景交互另做默认、边界、负值、同步和重置核对，静态检查不证明模型正确。

浏览器受限时说明未完成的检查。交付单文件 HTML，说明风格、验证结果与实际限制；不声称验证了统计因果或完整可访问性。

## 维护

更新注册表、封面、正文或基础样式后运行：

```powershell
python scripts/build_style_preview.py
python scripts/test_validate_report.py
```

实际浏览器验证预览切换与大小屏。四种旧 ID 保留；独立报告只需包含所选风格定义，不要求塞入全部主题。外部参考及本地适配见 [设计参考来源](references/design-influences.md)。
