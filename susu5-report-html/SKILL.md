# SUSU5 报告 HTML

当前版本：**v2.1.0** · 更新日期：2026-09-29。

把已确认的内容做成逻辑清楚、对比方便的报告。先让读者找到判断、关键证据和成立条件，再展开细节。根据问题选用表格、图表、文字或已验证的情景模型，不以展示数量衡量报告质量。

## 何时调用

- 用户提出或确认使用 HTML 交付报告、分析、总结、方案或文档时，立即进入本 Skill；不等用户再次指定排版工具。
- 对已有 HTML 报告重新设计、改风格或完善展示时也调用。
- 内容尚未分析完成时也先调用并明确分工：内容分析流程完成数据和结论，本 Skill 负责展示。不得因为内容未定而忽略已确认的 HTML 输出要求。
- HTML 代码教学、网站应用开发、邮件模板等不属于本报告 Skill 的自动触发范围。

## 每次交付必须先推荐和选风格

读取 [style-themes.md](references/style-themes.md)，按以下顺序执行：

1. 看本次内容的比较对象、表格密度、趋势分析、文字长度、读者和阅读场景，**推荐且只推荐一种风格**，给出与本次内容有关的理由。
2. **展示全部四种风格**：清晰商务、现代数据、温暖编辑、深色研判。用对比表写明视觉特征和适用场景，标出本次推荐。可附 [四种风格实样](assets/style-preview.html)，不能只报推荐名称或仅提供预览链接。
3. 请用户选择。工具可用时使用 `request_user_input_async`，提供全部四项；否则直接提问。等待期间可核对内容和材料，**没有选择或明确授权代选前，不生成本次报告成品**。预选项、用户未回复、超时均不代表同意。
4. 用户在本次请求中已点名风格，视为已选择；仍展示四种和内容推荐，按用户选定风格执行，不重复询问。用户明确说“你来选”“不用问直接做”时，展示推荐和四种选项后按授权代选，不再设置确认阻碍。

“每次”指每份新报告、独立交付或整体重新设计。同一份报告已完成选择后的改错、补图、数据更新和检查重试沿用本次选择，不反复询问；只有用户要求重新选风格或阅读场景实质改变时再选。历史报告风格或长期偏好可帮助推荐，不能自动代替新报告的选择。

每次生成前，将实际推荐、完整展示的选项和用户选择写入独立的风格记录，格式见 [style-themes.md](references/style-themes.md#选择记录)。不改动业务内容包。记录必须来自真实对话，不能为了通过检查虚构用户选择。维护 Skill 的模板和虚构风格示例不属于业务报告交付，无需发起选风格。

## 内容边界

优先使用经过验证的 JSON 内容包，也可接受已确认的文字、表格。只有原始数据时先交给内容分析流程；不能在本 Skill 内新增业务指标或推导未经确认的公式。情景交互只执行内容阶段已经确认的模型，输入、默认值、边界及预期结果见 [scenario-models.md](references/scenario-models.md)。

必须保留原有数值及 `display_value`、结论、证据强度、比较条件、时间范围、样本数量、限制、动作、负责人及有意义的内容顺序。缺失数据不填零；相关性不写成因果；猜测不写成事实。不从结论反推图表数据，不擅自排序或补算差值。

允许把已知全称用于表头、拆分长段和增加导航；不得以“润色”为由改写业务判断。发现矛盾或缺少影响结论的输入时先解决该部分，不能通过排版隐藏问题。

## 制作

确定本次风格后读取 [html-design-and-acceptance.md](references/html-design-and-acceptance.md)，以 [report-template.html](assets/report-template.html) 为起点。

- 按读者任务选择内容结构：快速判断用决策简报，核对多项证据用深度分析，探索已确认参数用情景测算。结构与四种视觉风格独立；可根据当前任务判断，无需新增一轮结构选择。选择依据及组件用法见设计参考。
- 首屏优先呈现总体判断、少量核心结论及关键条件；完整证据表随后展开。每个章节回答一个明确问题，不默认连续放两张表，也不为填版增造问题、机会或负责人。
- 每条核心结论有对象、关键证据、单位或范围以及成立条件。实际值、预估值和情景测算有文字标签；保留内容包的判断强度和有意义顺序。
- 对比优先用表格给精确值，用图表解释差异、趋势或分布。每张图表回答一个问题；不限制只能两张，也不为凑数量重复画图。
- 表头用完整名称，数字右对齐，单位明确。比例提供相应人数或分母。用颜色、字重和文字标签共同提示重点；普通分组差异不自动染成红绿。
- 默认正常阅读字号，正文约 18 像素、说明至少 15 像素。只有用户需要时才做大字版。
- 单文件、UTF-8、`lang="zh-CN"`、内嵌 CSS/JavaScript/SVG；无外部资源依赖。只正常上下滚动，无表格内部滚动，无打印或 PDF 功能。
- 一份报告只使用一种选定风格。四种风格在标题、区块、表格、图表安排上有区别，但不改变内容含义或数据。

## 检查与交付

执行：

```powershell
python scripts/validate_report.py <报告.html> --theme <风格参数> --style-selection <风格记录.json> --require-style-selection --content-package <内容包.json>
```

没有内容包时省略 `--content-package`，人工逐项核对全部数字、结论和限制。已有内容包可附 `presentation_checks`，为表格行、图表标注提供准确的文本核对序列；它不替代原始证据。

随后用获准的浏览器在 1440×900 和 1280 像素宽度实际检查：标题和导航不重叠，结论容易找到，数字与比较对象清楚，无横向溢出、截断、不可读颜色，图表与表格相符，折叠和键盘操作可用。静态检查通过不等于视觉验收通过；浏览器受限时明确说明尚未完成的检查，不绕过限制。

有参数交互时还要按 [scenario-models.md](references/scenario-models.md) 核对默认、边界、负值和重置，以及动态数值、文字、单位、颜色的一致性。静态脚本只检查输入声明和部分结构，不执行或证明模型正确。

交付单文件 HTML，说明所选风格、验证结果及实际存在的限制。不要宣称本 Skill 的静态检查验证了统计结论、因果关系或完整可访问性。
